## 4.3.4 Lesson Principles

### 4.3.4.1 Why Can LEDs Become Brighter and Dimmer?

Imagine you have a flashlight in your hand, and the switch only has two states: "On" and "Off." If you want to make the light a bit dimmer, the traditional way is to swap in a smaller battery, but that is too much trouble.

In the electronic world, we have a smarter way: **rapid switching**.

Certain pins on the ESP32S3 Pro development board (which we call PWM pins) can turn the current on and off at extremely high speeds (thousands of times per second).

*   If it stays on for half the time and off for half the time within 1 second, your eyes will perceive it as "half bright."
*   If the time it stays on is very short and the time it stays off is very long, you will perceive it as "dim."
*   If it stays on almost all the time and occasionally turns off, you will perceive it as "bright."

This technology is called **PWM (Pulse Width Modulation)**. Although it sounds like a long name, you only need to remember: **By controlling the proportion of "on" time, you can control the brightness.**

![Working Principle Diagram](placeholder)
*Figure: A PWM signal is like a rapidly blinking switch. The larger the duty cycle (the proportion of time at high level), the higher the average voltage and the brighter the light.*

### 4.3.4.2 Key Parameters: Duty Cycle and Frequency

To perfectly control PWM, we need to understand two key parameters:

1.  **Duty Cycle**:
    The duty cycle refers to the proportion of time the high level (power-on) takes up within a single pulse period. In MicroPython on the ESP32S3, we usually use 16-bit resolution, which means the duty cycle value can range from `0` (completely off, 0%) to `65535` (completely on, 100%). The larger the duty cycle, the brighter the LED.
2.  **Frequency**:
    Frequency refers to the number of pulse repetitions per second, measured in Hertz (Hz). If the frequency is too low (e.g., 10Hz), the human eye can see the light flickering; if the frequency is high enough (e.g., 1000Hz), due to the "persistence of vision" effect of the human eye, we will perceive the light as staying continuously on, with only its brightness changing.

### 4.3.4.3 Programming Logic: PWM Control Flow

To achieve the breathing light effect, the code logic is mainly divided into the following steps:

1.  **Initialize Hardware**: Select a pin that supports PWM, configure the PWM object, and set an appropriate frequency (such as 1000Hz).
2.  **Set Initial State**: Set the duty cycle to 0 to keep the LED off.
3.  **Fade-In Process**: Use a loop statement to gradually increase the duty cycle value from 0 to the maximum value (65535), increasing by a small step each time, and adding a short delay between steps.
4.  **Fade-Out Process**: Use a loop statement again to gradually decrease the duty cycle value from the maximum value down to 0, similarly decreasing by a small step each time and adding a delay.
5.  **Infinite Loop**: Put the above fade-in and fade-out processes into an infinite loop to make the breathing effect run continuously.

## 4.3.6 Sample Program

This code will make the LED connected to the io11 pin slowly brighten like breathing, reach its maximum brightness, and then slowly dim, repeating in a continuous loop.

```python
# Import the Pin and PWM classes from the machine module; Pin is used to specify pins, and PWM is used to output adjustable-brightness pulses
from machine import Pin, PWM
# Import the time module to control the delay speed of the breathing light
import time

# Create a PWM object using GPIO11, with the frequency set to 1000Hz (higher frequency reduces LED flicker perception)
led = PWM(Pin(11), freq=1000)
# Set the duty cycle to 0, starting in the off state (duty cycle range is 0~65535, where 0 is darkest and 65535 is brightest)
led.duty_u16(0)

# Infinite loop to keep the breathing light running continuously
while True:
    # Brightening loop: Duty cycle starts from 0, increasing by 256 each time until close to 65535
    for duty in range(0, 65536, 256):
        # Write the current duty cycle to PWM to control LED brightness
        led.duty_u16(duty)
        # Delay for 5 milliseconds; larger values make the breathing slower, smaller values make it faster
        time.sleep_ms(5)

    # Ensure the maximum brightness of 65535 is reached
    led.duty_u16(65535)
    # Maintain full brightness state for 200 milliseconds
    time.sleep_ms(200)

    # Dimming loop: Duty cycle starts from 65535, decreasing by 256 each time until close to 0
    for duty in range(65535, -1, -256):
        # Write the current duty cycle to PWM to control LED brightness
        led.duty_u16(duty)
        # Delay for 5 milliseconds, keeping the same speed as the brightening phase
        time.sleep_ms(5)

    # Ensure the minimum brightness of 0 is reached, completely turning off
    led.duty_u16(0)
    # Maintain fully off state for 200 milliseconds
    time.sleep_ms(200)
```

## 4.3.7 Code Explanation

To help you understand how the code works more clearly, we will break down the key parts in detail:

*   `from machine import Pin, PWM`: Imports the hardware control library. `Pin` is used to configure input and output modes for pins, and `PWM` is used to generate pulse width modulation signals on specified pins.
*   `led = PWM(Pin(11), freq=1000)`: Initializes physical pin 11 as a PWM output mode and sets the PWM signal frequency to 1000Hz. This frequency is high enough that the human eye cannot perceive any flicker.
*   `led.duty_u16(0)`: Sets the initial duty cycle to 0. `duty_u16` means using a 16-bit unsigned integer to set the duty cycle, ranging from 0 to 65535. 0 represents completely off.
*   `for duty in range(0, 65536, 256)`: This is a brightening loop. The `range` function generates a sequence of numbers from 0 to 65535 with a step size of 256. This means the duty cycle will gradually increase in 256 steps, making the brightness change smoother.
*   `time.sleep_ms(5)`: Pauses for 5 milliseconds after each change in the duty cycle. This delay determines the "breathing" speed. Without a delay, the brightness change would happen instantaneously, and the human eye wouldn't see the gradient effect.
*   `for duty in range(65535, -1, -256)`: This is a dimming loop. A step size of -256 means the duty cycle gradually decreases from the maximum value down to 0.

## 4.3.9 FAQ

**Issue: The LED light does not turn on at all**

*   **Cause**: There might be a loose connection, or the LED's positive and negative terminals might be reversed.
*   **Solution**: First, check if the jumper wires are plugged in tightly. Then, check the wire sequence of the LED module (since LEDs have polarity, reversing them prevents current flow). Ensure that the signal wire S is connected to io11, power V to VCC, and ground G to GND.

**Issue: The LED light is very bright, but has no "breathing" effect, staying constantly on**

*   **Cause**: The step size of the duty cycle change might be too large, or the delay time too short, making it hard for the human eye to distinguish the brightness transition; or the code failed to enter the loop correctly.
*   **Solution**: Check the `range` step size (e.g., 256) and `time.sleep_ms` delay (e.g., 5) in the code. If the step size is too large, reduce it (e.g., to 128 or 64); if the delay is too short, increase it appropriately (e.g., 10 ms or 20 ms).

**Issue: The LED light flickers severely, resembling a disco ball**

*   **Cause**: The PWM frequency is set too low, allowing the human eye to perceive the flashing on and off of the light.
*   **Solution**: Increase the PWM frequency in the code. Change `freq=1000` to `freq=5000` or higher (e.g., 10000). Usually, when the frequency is greater than 100Hz, the human eye will not perceive flickering.

**Issue: An error occurs when uploading the code**

*   **Cause**: The development board might not be properly connected, the wrong serial port might be selected, or the MicroPython firmware might not be flashed correctly.
*   **Solution**:
    1. Check whether the USB cable supports data transmission (some cheap cables only support charging).
    2. Check whether the correct COM port is selected in the programming software.
    3. Ensure that the MicroPython firmware has been successfully flashed onto the development board and that it is operating normally.

## 4.3.10 Safety Tips and Precautions

*   **Avoid Short Circuits**: Never directly connect the 3.3V/5V and GND pins with a wire. This will instantly generate a large current, potentially damaging the development board or your computer's USB port.

*   **Watch the Voltage**: This experiment uses low-voltage direct current (DC), which is very safe. However, do not attempt to connect the development board to a household 220V AC power outlet, as that is extremely dangerous!
*   **Handle Gently**: When plugging or unplugging Dupont wires, pinch the plug portion rather than pulling directly on the wire itself to avoid breaking the wire or damaging the development board's pins.
*   **Static Electricity Protection**: In dry seasons, the human body easily accumulates static electricity. Before touching the development board, it is best to first touch a grounded metal object (such as a water pipe or metal door handle) to discharge static electricity, so as not to breakdown the onboard precision chips.
*   **Power-Off Wiring**: Develop a good habit: when connecting or modifying any hardware wiring, always unplug the USB power cord first, and make sure the wiring is correct before powering on for testing.
