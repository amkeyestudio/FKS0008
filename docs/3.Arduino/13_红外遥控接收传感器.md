## 3.13.4 Course Principles

### 3.13.4.1 What is Infrared?

Imagine that the light emitted by a flashlight is light we can see. However, if there is a kind of light whose frequency is lower than red light (with a wavelength longer than red light), so low that the human eye cannot see it at all, that is infrared light. Although invisible, it does exist and carries energy and information. There is a small infrared transmitting tube in the remote control. When you press a button, it flashes at a very high speed, emitting specific infrared light pulses.

### 3.13.4.2 How Does the Infrared Receiving Module Work?

The infrared receiving module acts like a "sentinel" specifically waiting for infrared signals. Its surface has a black window housing a photosensitive element. When the infrared light emitted by the remote control hits this window, the internal circuit of the module converts the light signal into an electrical signal.

This module is very smart; it integrates a preamplifier and a bandpass filter internally, making it sensitive only to infrared signals of a specific frequency (usually 38kHz). This effectively filters out infrared interference from sunlight, fluorescent lights, or other ambient light. Once it receives the correct 38kHz modulated signal, it demodulates the baseband signal and tells the ESP32S3 Pro development board via the signal pin (OUT): "Hey, I've received data!"

### 3.13.4.3 Programming Logic: Detailed Explanation of the NEC Protocol

Infrared remote controls have various "languages" (protocols), and the most common one is called the NEC protocol. You can think of it as Morse code, using pulses of different lengths to represent 0 and 1.

A standard NEC protocol infrared frame consists of the following parts:

1. **Leader Code**: 9ms low level + 4.5ms high level, used to wake up the receiving end.
2. **Address Code**: 8-bit device address (and its 8-bit inverse code for verification).
3. **Command Code**: 8-bit button data (and its 8-bit inverse code for verification).

The ESP32S3 Pro development board needs a dedicated library (`IRremote`) to "translate" these complex pulse timings into numerical codes that we can understand (such as the command code `0xA2` or the full `0xFFA25D`). Thus, when we press "Volume +", the code will clearly tell us which key this is.

## 3.13.7 Example Program

This code will initialize the infrared receiving function and continuously monitor whether a remote control button is pressed. If so, it will print the hexadecimal code of the button in the Serial Monitor.

**Prerequisites**: You need to install the `IRremote` library in the Arduino IDE first. To do this, click `Tools` -> `Manage Libraries...` in the menu bar (or press `Ctrl+Shift+I`), search for `IRremote`, find the version developed by **Armin Joachimsmeyer**, and click Install.

```cpp
#include <IRremote.hpp> // Include the IRremote infrared remote control library

// Define the GPIO number connected to the infrared receiving module signal pin
#define IR_RECEIVE_PIN 48 

void setup()
{
    // Initialize serial communication and set the baud rate to 115200
    Serial.begin(115200);
    delay(1000); // Delay for 1 second to let the serial port stabilize

    Serial.println("ESP32-S3 IR Receiver Start");
    // Initialize the infrared receiver, specify the pin, and disable onboard LED feedback blinking
    IrReceiver.begin(IR_RECEIVE_PIN, DISABLE_LED_FEEDBACK);
    Serial.println("Waiting IR...");
}

void loop()
{
    // Check if an infrared signal has been successfully decoded
    if (IrReceiver.decode())
    {
        Serial.println("------ IR DATA ------");
        Serial.print("IR Value:");
        // Print the decoded command code in decimal format
        Serial.println(IrReceiver.decodedIRData.command);
        Serial.println("---------------------");
        
        // Resume receiving state, clear the buffer, and prepare to receive the next infrared signal
        IrReceiver.resume(); 
    }
}
```

## 3.13.8 Code Analysis

```cpp
#include <IRremote.hpp>
```

This line includes the `IRremote` library. Because infrared decoding is complex and involves precise microsecond-level time measurements, writing low-level drivers ourselves is difficult and prone to errors. Therefore, we borrow this powerful and mature utility library directly.

```cpp
#define IR_RECEIVE_PIN 48
```

We use the macro definition `#define` to define a constant `IR_RECEIVE_PIN` with a value of 48. This corresponds to the **GPIO48 (io48)** pin used during wiring. Using a macro definition instead of a raw number makes the code more readable, and if you want to change pins later, you only need to modify this single line.

```cpp
IrReceiver.begin(IR_RECEIVE_PIN, DISABLE_LED_FEEDBACK);
```

In `setup()`, we initialize the infrared receiver. The `DISABLE_LED_FEEDBACK` parameter is used to **disable** the onboard LED feedback blinking feature (if set to `ENABLE_LED_FEEDBACK`, it will blink when a signal is received). We choose to disable it here to avoid unnecessary pin conflicts or light pollution.

```cpp
if (IrReceiver.decode()) {
```

In `loop()`, this line constantly asks: "Has a new infrared signal been successfully decoded?" If not, it skips; if so, it enters the braces to execute the enclosed content.

```cpp
Serial.println(IrReceiver.decodedIRData.command);
```

This is the most crucial line. `decodedIRData.command` stores the specific numerical value (command code) of the remote control button.

```cpp
IrReceiver.resume();
```

After processing the current signal, you **must** call `resume()`. This is like telling the receiver: "I've finished looking at that signal just now, clear the cache and get ready to receive the next button!" Without this statement, the receiver will get stuck on the current data, causing you to read only a single button press.

## 3.13.9 Experimental Phenomenon

1. After uploading the code, open the "Serial Monitor" in the upper right corner of the Arduino IDE, and ensure the baud rate is set to **115200** (it must match `Serial.begin(115200)` in the code).

2. You will see prompt texts: "`ESP32-S3 IR Receiver Start`" and "`Waiting IR...`".

3. Pick up your infrared remote control, point it at the black window of the infrared receiving module, and press any button (such as the "Power" button or "Number 1" button).

4. If the wiring is correct and the code runs properly, a string of characters will be quickly printed in the Serial Monitor, for example:

   ```text
   ------ IR DATA ------
   IR Value:70
   ---------------------
   ```

5. Every time you press a button, a new line of code will be printed. If you press and hold a button, it might continuously print the same code or display the word `Repeat` (indicating a long-press repeat code), which is a normal physical phenomenon.

6. **Congratulations!** You have successfully made the ESP32S3 Pro "understand" the language of the remote control! Try pressing different buttons to see if their `Command` codes are all different.

## 3.13.10 FAQ and Troubleshooting

**Issue 1: The serial monitor shows no response, and pressing the remote control produces no output.**

- **Cause**: This may be due to wiring errors, especially if VCC and GND are reversed, or if the OUT pin is connected incorrectly. Alternatively, the remote control batteries may be dead.
- **Solution**:
  1. Check the pin definitions on the back of the module to confirm that VCC is connected to 5V and GND to GND.
  2. Point your phone's camera at the remote control's transmitting head and press a button. Check if a purple-white light flashes on the phone screen (phone cameras can capture some infrared light) to determine whether the remote control is transmitting normally.
  3. Confirm that the `IR_RECEIVE_PIN` macro definition in the code is set to 48, and that the jumper wire is indeed connected to the io48 pin of the development board.

**Issue 2: The printed codes are all 0 or garbled characters.**

- **Cause**: There is strong infrared interference in the environment (such as direct sunlight on the module), or the remote control protocol is not supported by the library by default.
- **Solution**:
  1. Cover the infrared receiving module with your hand to avoid direct strong light.
  2. Try replacing it with a remote control of another brand.
  3. Ensure that the latest version of the `IRremote` library is installed.

**Issue 3: Compilation error indicating `'IRremote.hpp' file not found`.**

- **Cause**: You have not installed the IRremote library, or the library path is not recognized by the IDE.
- **Solution**:
  1. In the Arduino IDE, click `Tools` -> `Manage Libraries`.
  2. Search for `IRremote`.
  3. Find the version developed by Armin Joachimsmeyer and click `Install`.
  4. Restart the Arduino IDE and try again.

**Issue 4: Pressing a button once prints multiple lines of different codes.**

- **Cause**: This is a normal decoding process. The library may first print the raw data (Raw Data) and then print the decoded command (Command).
- **Solution**: Pay attention to the line with `Command: 0x...`, which is the stable key value. If you need a cleaner output, you can add judgment logic in the code to filter out non-standard format data.

## Precautions and Safety Tips

- **Light Source Protection**: Although infrared rays are harmless to human eyes, **never** use strong light sources (such as laser pointers or high-intensity flashlights) to directly illuminate the receiving head at close range, so as not to burn out the internal photosensitive components.
- **Environmental Interference**: Try to avoid conducting infrared experiments in direct sunlight or in environments with a large amount of high-frequency fluorescent lighting. The infrared noise mixed in these ambient lights will seriously affect the receiving sensitivity.
