## 3.14.7 Example Program

This code reads the key values of the infrared remote control and controls the car's forward, backward, left turn, right turn, and stop movements based on the keys pressed.

```cpp
#include <IRremote.hpp>  // Include the IRremote infrared remote control library

// Define GPIO48 connected to the signal pin of the infrared receiving module
#define IR_RECEIVE_PIN 48

// ================= Motor Pin Definitions =================
#define MOTOR_AIN 40  // Channel A direction control (Left wheel)
#define MOTOR_AEN 41  // Channel A PWM control (Left wheel speed)
#define MOTOR_BIN 38  // Channel B direction control (Right wheel)
#define MOTOR_BEN 21  // Channel B PWM control (Right wheel speed)

void setup() {
  // Initialize serial communication with a baud rate of 115200
  Serial.begin(115200);
  delay(1000);  // Delay for 1 second to wait for the serial port to stabilize

  Serial.println("ESP32-S3 Infrared Receiver Initialized");
  // Initialize the infrared receiver, specify the pin, and disable onboard LED feedback blinking
  IrReceiver.begin(IR_RECEIVE_PIN, DISABLE_LED_FEEDBACK);
  Serial.println("Waiting for infrared signals...");

  // Set motor direction pins as output mode
  pinMode(MOTOR_AIN, OUTPUT); 
  pinMode(MOTOR_BIN, OUTPUT);

  // Configure PWM channels (ESP32 Arduino Core 3.x syntax)
  // Parameters: pin, frequency (1000Hz), resolution (8-bit, i.e., 0-255)
  ledcAttach(MOTOR_AEN, 1000, 8);
  ledcAttach(MOTOR_BEN, 1000, 8);

  // Ensure motors are stopped in the initial state
  stopMotor();
}

void loop() {
  // Check if an infrared signal has been successfully decoded
  if (IrReceiver.decode()) {
    Serial.println("------ Infrared Data ------");
    
    // Get the decoded 8-bit command code
    int irCommand = IrReceiver.decodedIRData.command;
    
    Serial.print("IR Value:");
    Serial.println(irCommand); 
    Serial.println("---------------------");
    
    // Execute corresponding actions based on the 8-bit command code
    // Note: Command codes may vary for different remote controls; modify according to the actual values printed on the serial monitor
    switch (irCommand) {
      case 70: // Corresponds to the 'Up' key on the remote control (Decimal 70)
        forward(200, 200); 
        break;
      case 21: // Corresponds to the 'Down' key on the remote control (Decimal 21)
        back(200, 200); 
        break;
      case 68: // Corresponds to the 'Left' key on the remote control (Decimal 68)
        left(200, 200); 
        break;
      case 67: // Corresponds to the 'Right' key on the remote control (Decimal 67)
        right(200, 200); 
        break;
      case 64: // Corresponds to the 'OK' key on the remote control (Decimal 64)
        stopMotor(); 
        break;
      default:
        // Do nothing if an undefined key is pressed
        break;
    }

    // Resume the receiving state, clear the buffer, and prepare to receive the next infrared signal
    // This step is critical; without it, the receiver will stop working after processing one signal
    IrReceiver.resume();
  }
}

// ================= Motor Control Functions =================

// Set PWM speed for left and right motors (0-255)
void setMotor(int leftSpeed, int rightSpeed) {
  ledcWrite(MOTOR_AEN, leftSpeed);  // Write PWM value for left wheel
  ledcWrite(MOTOR_BEN, rightSpeed); // Write PWM value for right wheel
}

// Move Forward
void forward(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, HIGH); // Left wheel forward
  digitalWrite(MOTOR_BIN, HIGH); // Right wheel forward
  setMotor(leftSpeed, rightSpeed);
}

// Move Backward
void back(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, LOW);  // Left wheel reverse
  digitalWrite(MOTOR_BIN, LOW);  // Right wheel reverse
  setMotor(leftSpeed, rightSpeed);
}

// Turn Left (Left wheel stops, right wheel moves forward)
void left(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, LOW);  // Left wheel stops
  digitalWrite(MOTOR_BIN, HIGH); // Right wheel forward
  setMotor(leftSpeed, rightSpeed);
}

// Turn Right (Left wheel moves forward, right wheel stops)
void right(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, HIGH); // Left wheel forward
  digitalWrite(MOTOR_BIN, LOW);  // Right wheel stops
  setMotor(leftSpeed, rightSpeed);
}

// Stop Motors
void stopMotor() {
  setMotor(0, 0); // Set speed to 0
}
```

## 3.14.8 Code Explanation

**1. Including Libraries and Defining Pins**
The code begins by including the `IRremote.hpp` library, which is the core for handling infrared decoding. Next, `#define` is used to define the IR receiver pin `IR_RECEIVE_PIN` as 48, along with four motor control pins. Using macro definitions makes the code more readable, and modifying pins later only requires changing a single place.

**2. Key Code Definition and Parsing**
In the `loop` function, we obtain the 8-bit command code via `IrReceiver.decodedIRData.command`. Keys from different remote controls correspond to different decimal values (e.g., `70` represents "Up"). The code uses a `switch-case` structure to match the retrieved command code with preset decimal values, thereby deciding which action to execute.

**3. Initialization in Setup**
In the `setup` function, the serial port is first initialized for debugging printouts. Then, `IrReceiver.begin()` is called to initialize the IR receiver, and onboard LED blink feedback is disabled to reduce resource usage. Finally, the motor control pins are set to output mode, and `stopMotor()` is called to ensure the smart car remains stationary upon startup.

**4. Decoding and Judging in Loop**
The `loop` function runs continuously. When `IrReceiver.decode()` returns `true`, it means an infrared signal has been successfully received and decoded. The program prints the command code and raw data for debugging purposes. Next, a `switch` statement evaluates the key and calls the corresponding motion function. **Special Note**: After the `switch` statement finishes, `IrReceiver.resume()` must be called; this clears the reception buffer and prepares the receiver for the next signal.

**5. Motor Control Functions**
Five motion control functions are defined at the bottom. `forward` and `back` control the forward and reverse rotation of the motors by setting direction pins to `HIGH` or `LOW`, and output PWM waves via `analogWrite` to control the speed. The `left` and `right` functions utilize the **differential steering** principle: for example, when turning left, the left wheel reverses while the right wheel goes forward, causing the car to turn left on the spot or within a very small radius. `stopMotor` sets the PWM value to 0, cutting off power to the motors.

## 3.14.9 Experimental Phenomena and Debugging

1.  **Upload the Code**: Compile and upload the code to the ESP32S3 Pro development board.
2.  **Open the Serial Monitor**: Open the Serial Monitor in the Arduino IDE and set the baud rate to **115200**.
3.  **Test the Buttons**: Pick up the infrared remote control, point it at the receiver head on the car, and press the "Up" button.
    *   **Serial Output**: You should see text similar to `IR Value: 70` and `Status: Forward`.
    *   **Car Action**: Both wheels of the car should spin forward simultaneously.
4.  **Test Other Buttons**:
    *   Press the "Down" button: The car moves backward.
    *   Press the "Left" button: The car turns left (left wheel reverses, right wheel goes forward).
    *   Press the "Right" button: The car turns right (left wheel goes forward, right wheel reverses).
    *   Press the "OK" button: The car stops immediately.
5.  **Success Indicator**: If pressing the buttons causes the car to accurately perform the corresponding actions, and the serial monitor shows correct hexadecimal print information, congratulations! You have successfully built an infrared remote-controlled smart car!

## 3.14.10 Common Issues and Troubleshooting

**Issue 1: Pressing the remote control yields no response in the serial monitor, and the car does not move.**

*   **Cause**: The IR receiver wiring might be incorrect, the remote control batteries might be dead, or the pin definitions in the code do not match the actual wiring.
*   **Solution**:
    1.  Check whether the VCC, GND, and OUT of the IR receiver are connected correctly. In particular, VCC and GND must not be reversed.
    2.  Point your phone's camera at the remote's transmitting head and press a button to see if a white light flashes on the phone screen (phone cameras can capture infrared light) to determine if the remote is transmitting normally.
    3.  Confirm that the value of `IR_RECEIVE_PIN` in the code (currently 14) matches the GPIO pin number you actually connected to.

**Issue 2: The serial monitor prints messages, but the command codes differ from those defined in the code.**

*   **Cause**: Every infrared remote control uses different encoding protocols and key codes; directly copying someone else's key values will not work.
*   **Solution**: First comment out the `switch` section and keep only the serial print code. After uploading, press various buttons on your remote and record the hexadecimal command code corresponding to each button in the serial monitor (e.g., `0x46`), then modify the values in the code's `switch-case`.

**Issue 3: The car's actions are reversed (e.g., moving backward when pressing forward).**

*   **Cause**: The positive and negative poles of the motor wires are reversed, or the `HIGH/LOW` logic for direction control in the code is inverted.
*   **Solution**: The easiest method is to physically swap the two wires of the corresponding motor on the motor driver module (e.g., swap A-IA and A-IB); or swap the `HIGH` and `LOW` states of `MOTOR_AIN` and `MOTOR_BIN` inside the `forward` function in the code.

**Issue 4: The car moves only for a split second and then stops, or its movement is stuttering.**

*   **Cause**: The infrared receiving library needs to be manually reset after processing a signal, or the battery power is insufficient, causing a voltage drop.
*   **Solution**: Ensure the battery has sufficient charge. Additionally, make sure to check whether `IrReceiver.resume()` is called at the end of the `loop` function. Without this line of code, the receiver enters a suspended state after processing a single signal, resulting in it only responding to a single button press.

## Safety and Precautions

*   Please test the car on open, flat ground to prevent it from falling from heights and damaging the hardware.
*   Do not let the car stall for a long time (wheels jammed while the motor is still powered); this will cause excessive current, overheating, and potential damage to the motor or driver module.
*   When wiring, disconnecting, or modifying hardware, **always disconnect the power supply** to prevent short circuits from burning out the ESP32S3 Pro development board.
*   Infrared remote control relies on line-of-sight control; please ensure there are no heavy obstacles between the remote control and the receiver head, and that the distance does not exceed 5-8 meters.
