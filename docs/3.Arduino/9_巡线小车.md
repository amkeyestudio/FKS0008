## 3.9.4 Course Principles

### 3.9.4.1 How do the "Eyes" of the Line-Tracking Sensor See?

 Remember the line-tracking sensor we learned in Lesson 7? It has a row of infrared transmitting and receiving tubes at the bottom. Simply put, it is like constantly asking the ground: "Are you white or black?"

*   **Encountering white ground**: Infrared light is reflected back, the sensor receives the signal, and outputs a high level (digital 1).
*   **Encountering a black line**: Infrared light is absorbed by black, very little is reflected, the sensor receives no signal, and outputs a low level (digital 0).

We have 5 such "eyes" arranged in a row. The middle eye is the most important because it is responsible for watching the road straight ahead.

### 3.9.4.2 How Does the "Brain" of the Car Think?

The ESP32S3 Pro development board is our commander. It checks the sensor status hundreds of times per second. Its thinking logic is very simple, just like keeping your balance when riding a bicycle:

*   **Situation A**: The middle sensor sees the black line -> **Go straight** (Great, the direction is correct!)
*   **Situation B**: The left sensor sees the black line -> **Turn right** (Oops, the car is leaning left, need to correct to the right)
*   **Situation C**: The right sensor sees the black line -> **Turn left** (Oops, the car is leaning right, need to correct to the left)

This is called "feedback control". We don't need complex mathematical formulas, just simple "if... then..." logic.

### 3.9.4.3 How Do Motors Cooperate to Turn?

To make the car turn, we don't need to turn the front wheels like a car. We rely on "differential steering":

*   **Turn Left**: The left motor stops or rotates slowly, while the right motor rotates quickly.
*   **Turn Right**: The right motor stops or rotates slowly, while the left motor rotates quickly.

## 3.9.5 Wiring Instructions

Wiring is the most critical step in the smart car experiment. Because there are many wires, it is easy to make mistakes. Please first disconnect the power from the ESP32S3 Pro development board (unplug the USB cable and battery), and then carefully connect according to the steps below.

**General Concept**:

1.  Connect the sensors to the input pins of the development board (via the I2C expansion board) to tell the development board what is detected.
2.  Connect the motor driver to the output pins of the development board to receive instructions from the development board.
3.  Connect the motors to the output terminals of the motor driver.
4.  **Important**: Motors require high current, so the battery supplies power directly to the motor driver. At the same time, you **must** connect the negative terminal of the battery and the GND of the development board together (common ground) so that they can "understand" each other.

**Detailed Pin Mapping Table**:

| 5-Channel Line Tracking Sensor | ESP32S3 Pro Development Board / Expansion Board Pin |      Description      |
| :----------------------------: | :-------------------------------------------------: | :-------------------: |
|              VCC               |                         5V                          | Sensor Power Positive |
|              GND               |                         GND                         | Sensor Power Negative |
|              SDA               |                         IO8                         |     I2C Data Line     |
|              SCL               |                         IO9                         |    I2C Clock Line     |

## 3.9.6 Sample Code

This code makes the smart car continuously read the status of the 5 sensors. If the middle sensor detects a black line, the car moves forward; if the left side detects it, the car turns right to correct; if the right side detects it, the car turns left to correct.

```cpp
#include <Wire.h>
#include <PCF8574.h>

// Initialize the I2C expansion board, address is typically 0x20
PCF8574 pcf8574(0x20);

// ==================== Line Tracking Sensor Pin Definitions ====================
// Note: The sensor outputs a low level (0) when detecting a black line, and a high level (1) when detecting a white line
#define OUTA P4  // Probe A (far left)
#define OUTB P0  // Probe B (left)
#define OUTC P1  // Probe C (middle)
#define OUTD P2  // Probe D (right)
#define OUTE P3  // Probe E (far right)

// ==================== Motor Pin Definitions ====================
#define MOTOR_AIN 40  // Channel A direction control (left wheel)
#define MOTOR_AEN 41  // Channel A PWM control (left wheel)
#define MOTOR_BIN 38  // Channel B direction control (right wheel)
#define MOTOR_BEN 21  // Channel B PWM control (right wheel)

// ==================== Speed Parameter Definitions ====================
#define BASE_SPEED 220  // Base driving speed
#define TURN_SPEED 220  // Speed when turning

// ===================================================

// Set the PWM speed for the left and right motors (0-255)
void setMotor(int leftSpeed, int rightSpeed) {
  ledcWrite(MOTOR_AEN, leftSpeed);  // Write left wheel PWM value
  ledcWrite(MOTOR_BEN, rightSpeed); // Write right wheel PWM value
}

// Move forward
void forward(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, HIGH); // Left wheel forward rotation
  digitalWrite(MOTOR_BIN, HIGH); // Right wheel forward rotation
  setMotor(leftSpeed, rightSpeed);
}



// Turn left function (left wheel stops/slows down, right wheel speeds up)
void turnLeft(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, LOW); // Left wheel forward rotation
  digitalWrite(MOTOR_BIN, HIGH); // Right wheel forward rotation
  setMotor(0, rightSpeed);
}

// Turn right function (left wheel speeds up, right wheel stops/slows down)
void turnLeft(int leftSpeed, int rightSpeed) {
  digitalWrite(MOTOR_AIN, LOW); // Left wheel forward rotation
  digitalWrite(MOTOR_BIN, HIGH); // Right wheel forward rotation
  setMotor(leftSpeed, 0);
}

// Stop motors
void stopMotor() {
  setMotor(0, 0); // Set speed to 0
}

void setup() {
  // Initialize serial communication, set baud rate to 115200
  Serial.begin(115200);

  // Set motor control pins as output mode
  pinMode(MOTOR_AIN, OUTPUT);
  pinMode(MOTOR_BIN, OUTPUT);
  pinMode(MOTOR_AEN, OUTPUT);
  pinMode(MOTOR_BEN, OUTPUT);
  
  // Set onboard LED pin as output (optional)
  pinMode(10, OUTPUT);

  // Initialize I2C expansion board
  pcf8574.begin();
  
  // Set line tracking sensor pins as input mode
  pcf8574.pinMode(OUTA, INPUT);
  pcf8574.pinMode(OUTB, INPUT);
  pcf8574.pinMode(OUTC, INPUT);
  pcf8574.pinMode(OUTD, INPUT);
  pcf8574.pinMode(OUTE, INPUT);

  // Stop motors in initial state
  motorStop();

  Serial.println("Line Tracking Start");
}

void loop() {
  // Read sensor states and invert them
  // Because the sensor outputs 0 when detecting a black line, inverting makes 1 represent a black line and 0 represent a white line, which is more intuitive
  int A = !pcf8574.digitalRead(OUTA);
  int B = !pcf8574.digitalRead(OUTB);
  int C = !pcf8574.digitalRead(OUTC);
  int D = !pcf8574.digitalRead(OUTD);
  int E = !pcf8574.digitalRead(OUTE);

  // Print sensor states to the Serial Monitor
  Serial.print("ABCDE: ");
  Serial.print(A);
  Serial.print(B);
  Serial.print(C);
  Serial.print(D);
  Serial.println(E);

  // Generate a 5-bit status code, packing the states of the 5 sensors into a single byte
  uint8_t state = 0;
  state |= (A << 4); // Shift A to the highest bit
  state |= (B << 3);
  state |= (C << 2);
  state |= (D << 1);
  state |= (E << 0); // Shift E to the lowest bit

  // Execute corresponding actions based on the status code
  switch (state) {
    case 0b01110: // Middle 3 sensors detect the black line, drive straight normally
      forward(BASE_SPEED, BASE_SPEED);
      break;

    case 0b11100: // Left sensors detect the black line, meaning the car is drifting left and needs to turn right
    case 0b11000:
    case 0b10000:
      turnRight(BASE_SPEED, TURN_SPEED);
      break;

    case 0b00111: // Right sensors detect the black line, meaning the car is drifting right and needs to turn left
    case 0b00011:
    case 0b00001:
      turnLeft(BASE_SPEED, TURN_SPEED);
      break;
      
    case 0b00000: // All sensors fail to detect the black line, meaning the car has strayed off the track, stop
      stopMotor();
      break;

    default: // Other complex states, drive straight at low speed to attempt correction
      forward(150, 150);
      break;
  }
  
  // Delay 20 milliseconds to control the loop frequency and prevent oscillation caused by overly rapid reactions
  delay(20);
}
```

## 3.9.7 Code Explanation

Let's break down this code to see how it commands the car.

**1. Defining Pins and Variables**
At the beginning of the code, we include the `Wire.h` and `PCF8574.h` libraries because the 5-channel line-following sensor is connected to the PCF8574 I/O expansion board via the I2C protocol, which saves precious GPIO pins on the ESP32S3. Next, we use `#define` to specify the sensor probes (OUTA~OUTE) and motor control pins (AIN, AEN, BIN, BEN). For easy subsequent adjustments, we extract the driving speeds into macros `BASE_SPEED` and `TURN_SPEED`.

**2. Reading Sensors**
In the `loop()` function, we use `pcf8574.digitalRead()` to read the voltage level state of each probe. There is a key detail here: the infrared sensor outputs a low level (0) when it detects a black line, and a high level (1) when it detects a white line. To make the code logic more intuitive (1 means a black line is present, 0 means no black line), we use the logical NOT operator `!` for inversion after reading. Subsequently, through the shift operation `<<` and bitwise OR operation `|`, 5 independent states are combined into a 5-bit binary state code `state`.

**3. Core Logic Judgment**
The core of the code is a `switch-case` structure that determines the car's actions based on the state code `state` generated in the previous step.

*   When the state is `0b01110`, it means the middle probe C as well as the surrounding probes B and D have detected the black line, indicating that the car is traveling in the center of the track. At this time, `forward()` is called to move straight.
*   When the state is `0b11100` or similar situations where the left probes detect the black line, it means the car is leaning to the left overall. At this time, `turnRight()` is called to make a right correction.
*   When the state is `0b00111` or similar situations where the right probes detect the black line, it means the car is leaning to the right overall. At this time, `turnLeft()` is called to make a left correction.
*   When the state is `0b00000`, it means none of the probes can see the black line, and the car has gone off track. At this time, `motorStop()` is called for an emergency stop.

**4. Motor Control Functions**
We have encapsulated four functions: `forward()`, `turnLeft()`, `turnRight()`, and `motorStop()`. Taking `turnLeft()` as an example, to achieve a left turn, we need to slow down or stop the left wheel while keeping the right wheel at a high speed. Therefore, we set the left wheel direction pin `MOTOR_AIN` to `LOW`, and the PWM value of the speed pin `MOTOR_AEN` to `0`; at the same time, we set the right wheel direction pin `MOTOR_BIN` to `HIGH`, and keep the speed pin `MOTOR_BEN` at the passed speed value. Through this differential speed control, the car can complete the turn smoothly.

## 3.9.8 Experimental Phenomena

When you upload the code to the ESP32S3 Pro development board and place the car on a piece of white paper with black tape drawn on it:

1.  **Initial State**: The car should remain stationary, or the motors should have a slight holding force.
2.  **Placed on the Line**: When you align the middle sensor of the car with the black line, the car should start **moving straight forward**.
3.  **Deviation Correction**:
    *   If you intentionally push the car a little to the right so that the black line appears under the left sensor, the car should immediately **turn right** to try to find the black line back.
    *   Conversely, if the black line appears on the right, the car will **turn left**.
4.  **Success Indicator**: The car can continuously drive along the curved black tape track without running off the track. Even if the track has a slight curve, it can automatically adjust its direction.

Open the Serial Monitor (baud rate 115200), and you will see a string of numbers jumping, such as `01110`, which means the middle sensor has detected the black line. When the car turns, you will see the position of `1` shift to the left or right.

## 3.9.9 Common Issues

**Issue: The car keeps spinning in place and doesn't move forward**

*   **Cause**: The wiring of the left and right motors might be reversed, or the left/right logic in the code is reversed. For example, the code says "turn left", but actually the left wheel turns and the right wheel doesn't, resulting in a right turn.
*   **Solution**: Observe the serial data. When the black line is on the left (the left side of the state code is 1), check whether the car turns right. If it turns left, please swap the motor control logic inside the `turnLeft` and `turnRight` functions in the code, or physically swap the wiring of the left and right motors.

**Issue: The car drives crookedly, like it's dancing**

*   **Cause**: The sensitivity is too high or the speed is too fast. The car turns violently when it deviates slightly, resulting in an oscillation back and forth.
*   **Solution**:
    1.  Lower the value of `BASE_SPEED` in the code, for example, from 220 to 150.
    2.  Add `delay(20)` or more (such as `delay(50)`) at the end of `loop()`, so that the car reacts more slowly and gives the mechanical structure a buffer time.

**Issue: The car doesn't move at all**

*   **Cause**: The battery is dead, or the enable pin of the motor driver is not connected properly, or the ground is not shared.
*   **Solution**:
    1.  Check the battery voltage.
    2.  **Key Check**: Is the battery negative terminal connected to both the motor driver GND and the ESP32S3 Pro GND? This is the easiest thing for beginners to miss.
    3.  Gently spin the wheels by hand to see if there is resistance, ruling out mechanical jamming.

**Issue: Sensor readings are all 1s or all 0s**

*   **Cause**: The ambient light is too strong and interferes with the infrared sensors, or the sensors are too high/too low from the ground.
*   **Solution**:
    1.  Adjust the potentiometer on the sensor module (if any) until the indicator light can switch sensitively at the boundary of black and white.
    2.  Make sure the sensors are about 1-2 centimeters away from the ground.
    3.  Avoid testing in direct sunlight; indoor lighting works best.

## 3.9.10 Safety and Precautions

*   **Entanglement Warning**: The wheels rotate at a high speed when the car is running. Please keep fingers, hair, and loose clothing away from the wheel axles and motor gears.
*   **Fall Prevention Warning**: Please conduct tests on an open and flat ground to prevent the car from rushing off the track and falling, which could damage the development board or sensors.
*   **Electrical Safety**: If you smell a burning odor or find the battery/motors abnormally hot, disconnect the battery power immediately!
*   **Power Management**: After the experiment, please be sure to turn off the power switch on the expansion board or unplug the battery box connector to prevent over-discharge damage to the battery.
